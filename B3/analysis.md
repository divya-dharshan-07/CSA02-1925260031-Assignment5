# B3 – Text vs Binary Persistence Investigation

The program verifies ten donor records in both formats, checks that all fields match after reading, and tests a valid stock update (record 3) and an out-of-range update (record 9). It then measures text and binary write/read CPU time and file size for 1,000, 10,000 and 100,000 donors. At 100,000 records it updates donor 50,000 directly in the binary file using fseek/fread/fwrite, and updates the matching text record by rewriting through a temporary file.

The invalid stock index is rejected because fread cannot obtain a complete record at that offset; the file is not modified. Binary fixed-size records support direct O(1) positioning and are usually smaller, but raw struct layout is implementation-dependent (padding, byte order and integer representation). Text is human-readable and easier to exchange, but an update normally requires a full rewrite. Record actual times and byte counts from the target computer; CPU time and storage performance vary by machine, compiler, filesystem and cache state. The program's read/write checks and ten-record verification should be retained in the screenshot evidence.
